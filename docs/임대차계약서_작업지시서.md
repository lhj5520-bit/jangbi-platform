참고 자료 (이 폴더에 있음):
- `docs/건설기계임대차계약서_양식.xlsx` — 원본 엑셀 양식
- `docs/임대차_표준약관_전문.md` — 표준약관 일반조건 전문 (추출본)

## 1. 시작 전 사용자에게 확인할 것 (AskUserQuestion 사용)

1. **임대인/임차인 매핑**: 임대인(건설기계 사업자) = 중기업체(suppliers) 또는 가온(자차), 임차인(건설업자) = 발주처(clients)로 이해되는데 맞는지. 자차 장비일 때 임대인이 가온 본인인지.
2. **저장 필요 여부**: 작성한 계약서를 DB에 저장·목록 관리할지, 아니면 거래명세서처럼 그때그때 작성→출력만 하면 되는지. (저장하면 Supabase 테이블 신설 필요 → 사용자가 SQL 실행해야 함)
3. **출력 형태**: 인쇄/PDF만? 거래명세서처럼 JPG 클립보드 복사·카톡 공유도 필요한지. 서명 페이지(/sign/[logId]) 같은 링크 공유 서명 기능이 필요한지.
4. **도장**: 임대인 날인에 업체 도장(suppliers.stamp_data)을 자동 표시할지.

## 2. 폼 구조 (xlsx 분석 결과 — 이대로 구현)

### 문서 제목: 건설기계임대차 표준계약서 (우측 상단: 표준약관 제10059호 / 2015.10.30. 개정)

**1. 목적물의 표시**
- 가. 건설기계 표: 건설기계명 | 등록번호 | 형식 | 보험(공제)가입현황(여/부) | 정기검사 여부(여/부) | 비고
- 나. 현장 표: 현장명 | 현장 소재지 | 발주자(원수급인) | 건설업자(임차인) | 건설기계 대여대금 지급보증 여부 | 비고

**2~5. 계약 조건**
- 2. 사용기간: YYYY년 MM월 DD일부터 ~ YYYY년 MM월 DD일까지 (날짜 2개 입력 → 문구 자동 생성)
- 3. 사용금액: 일당 금#,###원, 총 금액 금#,###원 (단, 대여거래 중 정산 요인이 발생한 경우 사후 정산, 부가가치세 포함) — 일당·총액 2개 입력 → 문구 자동 생성
- 4. 가동시간: "1일 8시간 기준, 월 200시간 기준" (기본값, 수정 가능)
- 5. 지급시기: 30일 / 60일 (원본 엑셀에 30, 60 값 존재 — 선택식 권장)

**확약 문구** (고정 텍스트):
"건설기계임대인과 건설기계임차인은 합의에 따라 붙임서류에 의하여 계약을 체결하고, 신의에 따라 성실히 계약상의 의무를 이행할 것을 확약하며, 이 계약의 증거로 계약서를 2통 작성하여 서명․날인 후 각 1부씩 보관한다"

**붙임서류**: 1. 건설기계임대차 표준계약 일반조건 1부 / 2. 건설기계임대차 계약 특수조건 1부(필요시)
**첨부서류 체크**: 사업자등록증사본 / 건설기계등록증 / 보험증권사본

**계약일** + 서명란:
- 임대인(건설기계 사업자): 상호 / 사업자등록번호 / 성명 (인) / 주소 — 도장 이미지 겹침 표시
- 임차인: 상호 / 사업자등록번호 / 성명 (인) / 주소

**2페이지: 표준약관 일반조건 전문** — `docs/임대차_표준약관_전문.md` 내용을 상수로 넣어 인쇄 시 계약서 뒤에 붙임 (표시/숨김 토글 권장)

## 3. 데이터 자동입력 매핑 (엑셀의 VLOOKUP을 대체)

- 중기업체 선택 → suppliers에서: 상호(name), 사업자등록번호(business_no), 성명(ceo_name), 주소(address), 도장(stamp_data)
- 장비 선택 (선택한 업체의 equipment) → 건설기계명(type을 굴삭기/덤프/화물로 라벨링 — **truck과 cargo 모두 '화물'**), 등록번호(plate_no), 형식(model 또는 spec), 정기검사(inspection_expire 존재+미래면 '여'), 보험(insurance_expire 존재+미래면 '여')
- 발주처 선택 → clients에서 임차인 상호/사업자번호/대표/주소 자동입력
- 모든 자동입력 값은 수동 수정 가능해야 함 (거래명세서의 editable-cell 패턴)

## 5. 이 코드베이스 특유의 함정 (위반 시 실제 장애 발생했던 것들)

- **문서 안 모든 input에 `width` 지정 + `minWidth: 0`** — 안 하면 PC는 멀쩡한데 폰에서 표가 테두리 밖으로 터짐 (한글 글꼴 폭 차이)
- **도장 이미지는 `position: absolute` + `zIndex: 10` + 마진 방식 수직 중앙** (translateY(-50%) 금지 — 캡처/줌 충돌 이력)
- **장비 type 라벨링에 truck 누락 금지** (DB 표준값이 truck)
- **equipment를 update할 일이 있으면 ownership 필드 절대 포함 금지**
- **Supabase 쓰기 후 error 확인 + alert 필수**
- 도장 데이터: suppliers.stamp_data(DB)가 원본, `ts_stamp_sup_{id}`(localStorage)는 캐시
- 사용자는 비개발자 — 터미널 명령 대신 deploy.bat 더블클릭 안내, 완료 후 폰 앱은 완전 종료 후 재실행해야 반영
- 모바일 화면 검증은 배포 후에만 가능. 배포 반영 확인은 HTML의 `dpl_` ID 변경 여부 (엣지 캐시 때문에 쿼리스트링 붙여 조회)
